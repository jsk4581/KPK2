## 실패 시 대체 경로 3개

| 대체 | 언제 | 어떻게 | 대가 |
|---|---|---|---|
| **ZIP 배포** | repo 접근·git이 안 되는 사람이 있다 | PM이 최신 `main`을 ZIP으로 공유 → 받은 사람은 새 폴더에 푼다(편집 중인 폴더 위에 덮어쓰지 않는다, `me/`는 옮긴다) → 상태는 GitHub 웹에서 본다 | 동기화가 느리다. 변경은 T0 중계 4항목으로 |
| **로컬 파일 데모** | 배포 경로가 막혔다 | `app/fallback.html` 더블클릭 → SMOKE 3단계 손으로 → 화면 녹화. SUBMISSION 「알려진 결함」에 "배포 URL 대신 로컬 시연" | F1(데모 URL 외부 접근)은 면제되지 않는다 — 제출 전에 반드시 다시 배포를 시도한다 |
| **PM 대행 커밋** | 웹 편집기도 막혔다 | 팀원이 Discord에 `기준 버전 · 대상 경로 · 변경 ID · 반영 확인 요청` 4항목으로 붙인다 → 그 파일 소유자(없으면 PM)가 검토해 반영하고 커밋 해시를 답한다 | PM 병목. 짧은 변경만 |

## 하지 않는 것

- 로컬 green·시뮬레이션 완주를 "준비 완료"로 보고하지 않는다.
- 행사 당일 계정·프로젝트를 새로 만들지 않는다 (계정 생성은 승인 대상 — 행사 전에).
- 이 파일에 연락처·계정 이름·토큰을 쓰지 않는다.
