## 1. 상품 구조 — 3층

| 층 | 무엇 | 누구에게 | 가격 | 역할 |
|---|---|---|---|---|
| ① 무료 앱 | **라이프로깅 앱** — 허락한 출처(사진·일정·대화·저장 링크·포트폴리오)가 자동으로 쌓이고, 지금 내 상태를 보여 준다 | 모든 개인 | 무료 | 기술력을 보여 주는 입구 · 사용자 확보 |
| ② 유료 앱 | **목표 프레임워크** — 인터뷰로 되고 싶은 모습을 구체화 → 실행 계획 → 습관 형성 알고리즘으로 계속 팔로업 → 목표에 어긋나면 알림·가이드 | 커리어 전환을 준비하는 개인 | 저가 월정액 (가설) | B2C 수익 — 서버 운영비를 덮는 수준 |
| ③ 브레인 | **의사결정 MCP 서버** — 자체 로직·프레임워크·온톨로지 정제를 API/MCP로 제공 | 라이프로깅이 중요한 기업 | API 호출·토큰 사용량 과금 | **궁극적인 수익원** |
| ④ 데이터 크레딧 | **사용자가 고른 데이터를 우리에게 판매 → 크레딧 지급**. 모인 데이터는 비식별·집계해 B2B에 판매 | 판매에 동의한 개인 → 기업 | 사용자: 크레딧 적립 (구독료 차감 등) · 기업: 데이터셋·인사이트 계약 | 사용자는 무료로 Pro를 쓰고, 우리는 B2B 데이터 수익을 얻는다 |

**핵심 기능 3개 (모든 층이 같은 브레인을 쓴다)**

1. **데이터 분석·연결** — 멀티모달 라이프로그를 분석하고, 쓰레기 데이터(실수로 찍은 사진, 광고·오발송 메시지, 원치 않는 위치)를 걸러 낸 뒤 온톨로지로 정제해 지금 상태를 빠르게 파악한다.
2. **목표 정의·프레임워크** — 커리어 목표(예: 카피라이터 → 교사)에 맞춘 로직과 계획 — 기간 → 분기 → 월 → 주 → 오늘.
3. **능동형 상시 모니터링** — 사진·대화·일정 등에서 목표와 어긋나는 흐름을 감지하면 알리고, 야단치지 않고 다음 행동을 작게 줄여 준다 (*"a rest day, not a missed day"*).

## 2. 비즈니스 모델 — B2C로 증명하고 B2B로 번다

```
  [개인] ──무료──▶ ① 라이프로깅 앱 ──업그레이드──▶ ② 목표 프레임워크 (월정액)
                         │                              │
                         └──────────┬───────────────────┘
                                    ▼
                  ③ BRAIN = 의사결정 MCP 서버 (도메인별 브레인)
                                    ▲
                  API·MCP 연결 · 토큰/호출당 과금
                                    │
  [기업] 이커머스 · 식품 · 헬스케어 · 스포츠 · (확장) HR · 법률 …
     └─ 자기 앱·워치에 브레인을 꽂는다 → 자기 고객이 우리 사용자가 된다 (영업 대행)

  [개인] ──데이터 판매 (본인 선택)──▶ 크레딧 ──▶ Pro 구독료에 사용
                     │
                     └─ 비식별·집계 ──▶ [기업] 데이터 구매 (트렌드·상품 기획)
```

### 2.1 순서

1. **B2C로 먼저 모은다** — 무료 라이프로깅 앱으로 들어오고, 커리어 위기 때 유료 프레임워크로 올라간다.
2. **성공 사례로 증명한다** — 새 직무 진입, 첫 수익, 창업 같은 사례가 가장 강한 셀링 포인트이자 모멘텀이다.
3. **B2B로 확장한다** — 증명된 브레인을 기업이 자기 서비스에 붙이고, 사용량만큼 낸다.

### 2.2 성장 엔진 — 도메인별 브레인

- 기본 프레임워크는 하나, 학습은 **도메인별로 갈라지고 세분화**된다 (프리랜서 라이터 · CS 담당자 · 엔지니어 · DB 엔지니어 …).
- 사용자가 자기를 정의하고 들어오면 MCP 서버가 그 도메인의 브레인과 로직을 고른다.
- 사용자의 시행착오·요청이 쌓일수록 그 도메인의 의사결정·팔로업 로직이 정교해진다 → 그 도메인 기업(예: 법률 브레인이 성숙하면 로펌)에 API를 열어 판다.

### 2.3 네트워크 효과 — 커뮤니티

- 사용자끼리 돕고 네트워킹하며 새 비즈니스를 만든다.
- 성공 후기(수익 창출 · 창업 · 새 직무 진입)를 중심으로 커뮤니티가 커진다.
- 우리는 그 중심에서 알고리즘·로직을 계속 고도화하는 **심장** 역할을 한다. (오늘 데모 범위 밖 — 로드맵)

### 2.4 데이터 크레딧 루프 — 사용자가 데이터를 팔고, 우리가 B2B에 판다

1. 사용자가 **판매할 데이터 범주를 직접 고른다** (예: 관심사·목표 방향·활동 패턴은 판매, 위치·대화 원문은 비판매).
2. 판매한 만큼 **크레딧**을 받는다 → Pro 구독료 차감 등 앱 안에서 쓴다. 실직 상태여도 데이터로 유료 기능을 쓸 수 있다.
3. 우리는 판매 동의 데이터만 **비식별·집계**해 B2B에 판다 — "이 직군 사람들이 어떤 방향으로 이동하려 하는가" 같은 지향·트렌드 데이터.
4. 판매 동의는 **언제든 철회**할 수 있고, 철회 뒤 데이터는 다음 판매분에서 빠진다.

**왜 강한가**: 사용자는 자기 데이터의 값을 직접 돌려받는다 (지불 능력 문제 완화). 기업은 어디에도 없는 "되고 싶은 모습" 지향 데이터를 얻는다. 브레인 판매(토큰)와 데이터 판매(계약)가 두 개의 B2B 수익원이 된다.

### 2.5 B2B 예시 시나리오 (설명용 — 접촉·계약 없음)

| 산업 | 예시 | 브레인으로 하는 일 |
|---|---|---|
| 도서·콘텐츠 (피치 권고 예시) | 대형 도서 플랫폼이 자사 사용자에게 라이프로깅을 제공하고 브레인을 연결 | 동의한 사용자들의 비식별 관심·지향 통계 → 새 트렌드의 책·콘텐츠 기획. 테크니컬 라이터·번역가 페르소나와 바로 이어진다 |
| 스포츠·웨어러블 | 스포츠 브랜드 워치 앱에 브레인 연결 | 비식별 행동 패턴·라이프 오리엔테이션(예: 다이어트 관심도) 분석, 목표별 습관 루프 |
| 헬스케어·식품 | 웰니스 앱·식품 기업 | 목표·상태 기반 맞춤 프로그램·상품 기획 |
| HR·아웃플레이스먼트 | 감원 기업·채용 플랫폼 | 대상자 전직 계획·모니터링 (§3 가격 참고) |
| 법률 (도메인 브레인 확장) | 로펌 | 법률 도메인 브레인 API, 토큰·건당 과금 |

자체 라이프로깅 수단이 없는 기업에는 **수집 프로토콜까지 묶어서** 제공할 수 있다.

## 4. 데이터 원칙 — 본인이 판 데이터만 판다

| 원칙 | 내용 |
|---|---|
| 판매는 본인 선택 (opt-in) | 기본값은 **비판매**. 사용자가 판매할 범주를 고르고, 판 만큼 크레딧을 받는다. 언제든 철회 |
| 원본은 팔지 않는다 | 원본은 사용자 기기(온디바이스·엣지)에서 처리한다. B2B에는 판매 동의 데이터의 **비식별·집계본**만 간다 |
| 민감 범주는 따로 | 위치·GPS·대화 원문·건강 데이터는 기본 비판매. 원치 않으면 수집부터 뺀다 |
| 전송 보호 | 보낼 때 토큰화해 위험을 줄인다 |
| 쓰레기 데이터 제거 | 실수로 찍은 사진, 광고·오발송 메시지, 맥락에 안 맞는 대화는 브레인에 들어가기 전에 걸러 낸다 — 데이터 품질이 곧 판단 정확도이자 데이터 상품 가치다 |
| 오늘 데모 | 라이프로그는 전부 **[SIMULATION] 합성 데이터** (PRD v2 문장 5). 데이터 판매·크레딧은 데모에 없다 |

**세일즈 주의 (반드시 같이 말할 것)**
- 라이프로그(위치·사진·생활 패턴)는 이름을 지워도 재식별 위험이 큰 데이터다. 그래서 개인 단위가 아니라 **집계**로만 판다고 말한다.
- 미국은 데이터 판매에 규제가 있다: 캘리포니아 CCPA/CPRA는 판매 고지·거부권과, 데이터 대가로 혜택을 주는 프로그램에 "금전적 인센티브 고지"를 요구한다. 워싱턴주 My Health My Data Act는 건강 데이터 판매에 서명된 별도 승인을 요구한다. FTC는 "익명화했다"며 판 위치·브라우징 데이터를 제재한 사례가 있다. (🟡 이번 세션에서 원문 미확인 — 법률 자문 아님, 슬라이드 인용 전 확인)
- 그래서 메시지 순서는 **① 브레인을 판다 → ② 사용자가 원하면 자기 데이터를 팔고 크레딧을 받는다**. 데이터 판매를 첫 문장으로 쓰지 않는다.

**세일즈 한 줄**: *"Your data, your choice — share it and get paid in credits, or keep it private and still get the brain."*

## 10. 예상 질문과 답 (결선 Q&A 7분)

| 질문 | 답의 뼈대 |
|---|---|
| ChatGPT랑 뭐가 다른가? | ChatGPT는 매번 처음 만나는 사이다. 우리는 내 데이터로 나를 알고, 되고 싶은 모습을 알고, 계획 뒤에도 매일 따라온다. |
| 돈은 어디서 버나? | B2C는 무료 → 저가 구독으로 사용자를 모으고 증명한다. 수익은 B2B 두 갈래 — 기업이 브레인을 호출하는 사용량 과금, 그리고 판매 동의 데이터의 비식별·집계 라이선스. |
| 실직자가 돈을 낼 수 있나? | 무료로 시작한다. 데이터 크레딧으로 Pro를 쓸 수 있고, 고용주가 퇴직 패키지로 12개월(~$100/인)을 내 줄 수 있다 — 아웃플레이스먼트($1,660/인, E18)보다 훨씬 싸다. |
| 데이터를 파는 회사 아닌가? | 첫 상품은 브레인이다. 데이터는 사용자가 고른 것만, 크레딧을 주고 사서 비식별·집계로 판다. 기본값은 비판매, 언제든 철회. 원본은 기기에서 처리한다. |
| 사용자가 왜 데이터를 파나? | 크레딧으로 유료 기능을 쓸 수 있어서다. 일이 줄어 구독료가 부담인 사람에게 "내 데이터로 내 커리어 준비 비용을 낸다"는 선택지를 준다. (가설 — 사용자 인터뷰 없음) |
| 왜 기업이 브레인을 사나? | 기업은 기록은 있지만 "이 사람이 무엇이 되려 하고, 지금 계획대로 가나"를 판단하는 엔진이 없다. 만들지 않고 꽂아 쓰고 쓴 만큼 낸다. (가설 — 기업 인터뷰 없음) |
| 해자는? | 도메인별 브레인. 사용자 시행착오가 쌓일수록 각 도메인의 판단·팔로업 로직이 정교해지고, 성공 사례 커뮤니티가 사용자를 다시 데려온다. |
| 1,000만 명은? | 비치헤드 약 70만(E25) → 지불 가능 약 300만(E67) → BLS 감소 전망 직업 약 1,180만(E66). 모두 가설이라고 먼저 말한다. |
| 오늘 실제로 도는 건? | §8의 "실제로 돈다" 칸만. 나머지는 시뮬레이션·로드맵이라고 먼저 말한다. |

## 11. PM 결정이 필요한 것

1. **B2C 가격 구조** — 라이프로깅은 무료, 목표 프레임워크는 저가 월정액 (Build 12:48 프리미엄 안)으로 확정할지.
2. **데이터 크레딧 모델 표현** — 피치에서 "① 브레인 판매 → ② opt-in 데이터 판매 + 크레딧" 순서로 말할지, 2장 덱에 데이터 판매를 넣을지 (규제 질문 대비 필요).
3. **피치 B2B 대표 예시** — 도서 플랫폼(라이터·번역가 페르소나와 직결) vs HR·아웃플레이스먼트(미션과 직결). 실명 회사는 쓰지 않거나 "예시"로만.
4. **토큰 단가** — 숫자 없이 "usage-based"로만 표기 (권고).
5. **마케팅 플랜 소유자** — §7을 GTM이 받아 채널 규모·비용을 E-ID로 보강.
6. **크레딧 설계** — 판매 범주(기본 비판매 범주 포함)·크레딧 환산·철회 처리. 오늘은 숫자 없이 구조만.
